MONKEY INC BOT: HOST GUIDE
===========================

Host commands are all under /host. You can use them if you have the host role (HOST_ROLE_ID)
or the Manage Server permission. Replies are only visible to you.

Players use the commands in user_guide.txt. Read that first so you know what players see.


HOST COMMANDS AT A GLANCE
-------------------------
  /host       status, availability, import, squads, damage_history, remind_now
  /config     reminders, damage_logs, squad_time, squad_remove   (settings)
  /player     add, edit, link
  /character  add, edit, remove


WHO CAN SEE THE HOST COMMANDS
-----------------------------
/host, /config, /player and /character are hidden from the command list for everyone
except members with the Manage Server permission. Discord doesn't let a bot show commands
to a role by itself, so a server admin does this once for EACH of the four:

  1. Server Settings > Integrations > Monkey Inc. > Manage.
  2. Under Commands, click /host (then /config, /player and /character).
  3. Add the host role (the one in HOST_ROLE_ID) and set it to allowed (✅).

Hosts may need to restart Discord (or press Ctrl+R / Cmd+R) before they appear.

Visibility only affects the command list. Every one of these commands also checks that the
user has the host role (or Manage Server), so even someone who sees it can't use it without
that role.

Optional: to show the player commands only to your player role, go to the same page. Under
Roles & Members at the top, add @everyone and set it to denied (❌). Then add the player
role and set it to allowed (✅). Keep the host-role overrides from step 3 in place.


KEY IDEAS
---------
- Squad order: every list of squads starts in time order. 🔀 "Sort by squad #" (on
  /host availability's overview and "All squads", /host squads, a player's availability,
  and the player screens) switches to squad-number order. It's remembered per person and
  used on every screen until you switch back with 🔀 "Sort by time".
- Week: a week runs Sunday to Saturday in the bot's timezone (default US Eastern,
  BOT_TIMEZONE). Most host commands take week: "Next week (upcoming)" (the default) or
  "This week (current)".
- Availability levels: 🟢 Preferred, 🟡 Available, 🔴 Not Available.
- Default vs. weekly: every player has a default schedule. For any week, the bot uses the
  player's weekly update if they submitted one. Otherwise it uses their default.
- Confirmed: a player counts as confirmed for a week once they press "No change" or save a
  weekly update. Viewing their schedule doesn't count.
- Advance submissions: players can change their availability for any of the next 8 weeks
  ("Update a week" in /cq availability). Those changes count as confirmed for that week. They show up in
  /host status and /host availability once that week is "next week" or "this week".
- Player status:
    active     Normal roster member. Counted in /host status and /host availability.
    inactive   Not currently running. Ignored by status and availability.
  (A CHARACTER's status is separate: see character status, ⭐ static / ⏳ flex /
  💤 inactive.)
- Slotting stays in the Google Sheet. The bot learns squads and slot status when you upload
  the sheet with /host import.


1. CHECKING AVAILABILITY
------------------------
/host status [week]
    How many ACTIVE players have confirmed (e.g. 41 / 73), with one line each for
    ✅ No change, ✏️ Updated and ⏳ Not confirmed yet. Lists every player who SUBMITTED A
    SCHEDULE CHANGE for the week. Look up someone's changed
    schedule with /host availability player:<name>.
    The 📋 "Open availability" button opens the /host availability view for the same week
    (as a new message, so the status stays above it).
    It also lists CHARACTER STATUS CHANGES from the last 7 days, with before and after:
        Alice: Ace (NL) ⭐ Static → 💤 Inactive
        Bob: Bolt (NL) ⭐ Static → ⏳ Flex (by host)
    If a character changed more than once, you see where it started and where it ended up;
    one changed and then changed back isn't listed. "(by host)" = changed with
    /character edit rather than by the player. Every change is kept in the bot's database.

/host availability [player] [week]
    Without a player: availability for every active player.
      - The message shows, per squad, how many players are 🟢 / 🟡 / 🔴.
      - Buttons and a squad dropdown underneath help with slotting. The buttons are
        📋 Overview, 🟢 Preferred, 🟡 Available; the one for what's on screen is blue
        (the message opens on Overview).
          📋 Overview                   The counts per squad.
          🟢 Preferred / 🟡 Available   Pick the level to show.
          Squad dropdown: "All squads"  Every squad with the players at that level (names).
                                        ⏳ marks players who only have ⏳ Flex characters at
                                        that level; they're listed after players with a
                                        static character.
          Squad dropdown: a squad       That squad's characters at that level, grouped by
                                        class under role headings, on these pages:
                                          Page 1  HP:   DRK, ARAN
                                                  BSP:  BSP
                                                  SI:   BUCC, TB
                                          Page 2  CRIT: DB, BM, MM, WA
                                          Page 3  DPS:  every other class, A-Z
                                        Use ◀ ▶ to move between pages. A page with no
                                        characters is skipped.
                                        Each class shows its icon and a count, e.g.
                                        "<icon> DRK (6)", then one line per character:
                                        damage - name, e.g. "• 4.3b - ragu". Damage is
                                        in billions (27.5-minute scale), rounded down to one
                                        decimal (3.08 -> 3.0b), in a shaded box so it's easy
                                        to skim; "?" = no damage recorded.
                                        Order: static characters first, then ⏳ Flex ones; each
                                        highest damage first (no damage last).
                                        Inactive characters are left out.
                                        🔀 "Group by player" switches to players A-Z, each
                                        with their characters as bullets (class icon and
                                        name, or "ragu/DRK" without an icon), ordered:
                                          1. static, then ⏳ flex
                                          2. class group: Warrior (HERO PAL DRK DW ARAN),
                                             Magician (FP IL BSP BW EVAN), Archer (BM MM
                                             WA), Thief (NL SHAD DB NW), Pirate (BUCC SAIR
                                             TB)
                                          3. character name
                                        🔀 "Group by class" switches back.
                                        Busy squads spread over pages (◀ ▶). In either
                                        grouping, anything too long for one page continues
                                        on the next, marked "(cont.)" in the class view.
      - Availability here is per character: the player's weekly change (or default), plus
        any availability the player set for that character ("Character availability" in
        /cq availability).
        When both exist, the less available one counts.
    With a player: that player's availability for the week (their weekly update, or their
    default if they didn't submit one), their confirmation, and their characters with any
    per-character overrides.
    Tip: start typing a name, Discord handle, or character IGN, then pick from the list.


2. MANAGING PLAYERS
-------------------
/player link player:<player> member:<@member>
    Link a roster player to a Discord account. Use this when a player's Discord username
    changed and the bot says it can't find them. Players are otherwise linked
    automatically the first time they use the bot.

Only hosts can add or change players and characters. Players can view their characters
(/cq characters) and set their own availability, but can't edit the roster.

/player add name:<name> [member:<@member>] [username:<discord username>] [status]
    Add a new player. Pick their Discord account with member (recommended). If they're
    not in the server yet, give their Discord username instead; they're linked
    automatically the first time they use the bot. Status defaults to Active.
    Then add their characters. The player sets their usual availability with "Update my default" in
    /cq availability.

/player edit player:<player> [name:<new name>] [status:<Active | Inactive>]
    Rename a player, change their status, or both.

/character add player:<player> ign:<IGN> job:<job> buff:<role> [dmg] [status]
    Add a character to a player. Job suggestions come from jobs already on the roster.
    buff is one of DPS, HASTE, SE, HSH, SI/TL, SI, THORNS, HB.

/character edit character:<IGN> [job] [buff] [dmg] [status] [owner]
    Change a character's job, role, damage or status. The dmg you enter is a fallback: once
    the character has runs from uploaded damage logs, those take priority.
    owner moves the character to another player (pick from the suggestions). Its damage
    history, character-specific availability and status move with it.

Character status (⭐ static / ⏳ flex / 💤 inactive) shows which characters a player wants
slotted. Players choose Static or Flex themselves with the "Set character status" button in
/cq characters. Only hosts can mark a character 💤 Inactive (or change it back), with
/character add or /character edit (status option); players see inactive characters as
locked. It starts as Static for
characters marked Perm on the sheet, Flex otherwise; /host import never changes it.

/character remove character:<IGN>
    Remove a character, including its damage history and availability overrides.


3. UPDATING THE ROSTER FROM THE GOOGLE SHEET
--------------------------------------------
/host import file:<roster.csv>
    In Google Sheets: File > Download > Comma Separated Values (.csv) on the CQ Roster tab.
    Then attach that file to /host import.

    What it does:
      - Updates every character's job, buff, dmg, run time, squad, slot status and perm.
      - Adds new players and characters it hasn't seen before. New players start as
        active, with a default schedule taken from the sheet's Squad 1..N columns.
    Damage from the sheet (Dmg/27.5, or Dmg when that's empty) is assumed to be already
    scaled to a 27.5-minute run, so it's stored as-is. It's only used for characters
    with no uploaded damage logs.
    What it does NOT change:
      - Player statuses (active/inactive).
      - Availability players already set in the bot (default, weekly or per-character).
      - Characters that are in the bot but missing from the CSV (they're listed in the reply).

    The CSV is matched by column names (IGN, Name, Discord, Job, Buff, Squad, Dmg,
    Run time, Perm, Status, Squad 1..N), so extra or reordered columns are fine.


4. SQUAD TIMES
--------------
The bot keeps a recurring weekly schedule for each squad (day + time in the bot timezone),
first loaded from bot_data/squad_timings.txt. You can move a squad for one week, or change
it permanently.

/host squads [week]
    List squad times, shown in your own timezone. Squads moved for that week are marked ✏️.

/config squad_time squad:<n> [day:<weekday> time:<HH:MM>] [permanent] [reset]
    Time is 24-hour, in the bot timezone (e.g. 21:30).
      permanent:False (default)  Moves the squad for NEXT WEEK only.
      permanent:True             Changes the recurring schedule for all future weeks.
                                 Also use this to ADD a new squad number.
      reset:True                 Undoes next week's one-off move for that squad, putting it
                                 back on the recurring schedule. Leave out day and time.
    Tip: Daylight saving changes can shift the game server's times relative to Eastern.
    When that happens, use permanent:True to update the recurring schedule.

/config squad_remove squad:<n>
    Permanently remove a squad from the schedule.


5. WEEKLY REMINDERS
-------------------
The bot automatically posts the reminder (with the View my availability / No change / Update
this week buttons) in the CQ channel for the upcoming week. By default it posts twice:
Wednesday and Friday at 18:00 (bot timezone).

The reminder @mentions the player role set in PLAYER_ROLE_ID (in .env). This includes
reminders posted with /host remind_now. Leave PLAYER_ROLE_ID empty for no ping. The role
must allow @mentions (Server Settings > Roles > "Allow anyone to @mention this role"),
otherwise the mention shows but nobody is notified.

The reminder message is the same for everyone. Each player's personal availability appears
only to them when they press "View my availability".

/config reminders [channel] [remind_days] [remind_time] [deadline_day] [deadline_time] [enabled]
    Run it with no options to see the current settings and this cycle's reminder and
    deadline times. Set any option to change it. Times are 24-hour in the bot timezone.
      remind_days    One or more days, comma-separated, e.g. "Wed, Fri" or "Thu".
      remind_time    The same time is used for every reminder day.
    Defaults: reminders Wednesday and Friday 18:00, deadline Saturday 12:00 (the week
    before the squads run).
    Changing the days or time only affects future reminders. The bot won't immediately
    post one whose new time has already passed.
    The deadline is shown in the reminder. Players can still submit after it.

/host remind_now
    Post the reminder for next week immediately, in the configured channel (or the current
    channel if none is set). If a scheduled reminder is due at that moment, it won't
    also be posted. Later scheduled reminders still go out as normal.

If the bot is offline when a reminder is due, it posts the missed reminder when it comes
back up. Reminder buttons keep working after the bot restarts. A reminder for a week that
has already finished no longer accepts changes.


6. CLASS ICONS
--------------
The squad details in /host availability show a class icon next to each character. The
icons come from image files in bot_data/class_icons/ on the machine running the bot:

    bot_data/class_icons/DRK.png
    bot_data/class_icons/NL.png
    bot_data/class_icons/BSP.png   ... one per class, named exactly like the Job on the roster

  - PNG, JPG or GIF, up to 256 KB. A square image around 128x128 works best.
  - The bot checks the folder when it starts and every 10 minutes after that:
      new file       -> uploaded
      changed file   -> replaced
      deleted file   -> icon removed (the class name shows instead)
  - A file Discord rejects (e.g. too large) is skipped, and the reason is written to the
    bot's log. It's retried once you replace the file.
  - If the folder doesn't exist, existing icons are left as they are.
  - Classes without an icon show as "ragu/DRK".
Icons are stored by Discord as the bot's own emoji, so they work in any server and don't
use your server's emoji slots. The folder is git-ignored (class art is usually the game's
copyrighted artwork), so copy it to the server yourself, like the rest of bot_data/.


7. DAMAGE LOGS (#queen-logs)
----------------------------
After a run, post the damage log .txt file in #queen-logs as a normal message attachment
(drag and drop). You can attach several logs to one message. Only hosts' uploads are
processed. Files posted by anyone else are ignored.

The bot reads the bottom of the file:
    [Start Time] 27-09-2026 01:50:49        <- game server time (LOG_TIMEZONE, Sydney)
    [Finish Time] 27-09-2026 02:15:09
    >>CharacterName: 4,027,079,300 | deaths: 2

What happens:
  - Each character's damage for the run is scaled to a 27.5-minute run, in billions:
        damage / 1,000,000,000 x 27.5 / run minutes
    e.g. 4,027,079,300 over 24.3 minutes -> 4.55
  - The character's damage becomes the AVERAGE OF THEIR LAST 3 RUNS (change the number
    with /config damage_logs). This is the "dmg" shown by /cq characters.
  - The bot reacts ✅ when a log is saved. It replies only if something needs attention.
  - Names the bot can't match to a roster character are FLAGGED: the bot adds a ⚠️
    reaction and replies to you (with a ping) listing those names. Everyone else in the
    log is still saved as normal.
  - Names are matched to characters on the roster, ignoring capital letters.

The bot replies when:
  - Names aren't on the roster (⚠️, pings you). Only those names are skipped. Check the
    spelling, or add the character (/character add or /host import), then
    post the same log again. Only the missing characters are added; the rest of the run
    isn't counted twice.
  - The run was already uploaded (same start and finish time). Nothing is saved twice.
  - The file isn't a damage log (no start/finish time or damage lines).

Undo: delete your upload message. The bot removes that run and recalculates damage for
everyone in it. A character with no runs left goes back to their damage from the roster
sheet, or the value they entered.

Damage from logs always takes priority. /host import and /character edit dmg only
change the fallback value, used while a character has no logged runs.

/config damage_logs [channel] [average_runs]
    Run it with no options to see the settings. channel: where logs are posted (default: any
    channel named #queen-logs). average_runs: how many recent runs to average (default 3).
    Changing this recalculates every character.

/host damage_history character:<IGN>
    A character's current damage and their last 15 runs: raw damage, run length, and
    scaled damage. ★ marks the runs counted in the average.


8. TROUBLESHOOTING
------------------
- "Only hosts can use this command": you need the host role or the Manage Server
  permission.
- No reminder posted: check /config reminders. Are reminders enabled, and is a channel set?
  Does the bot have permission to send messages and embeds in that channel?
- A player can't be found: /player link them to their Discord account.
- Wrong squad times: see /host squads, then fix with /config squad_time.
- A damage log got no ✅ and no reply: check it was posted in the logs channel
  (/config damage_logs), as a .txt attachment, by someone with the host role.
