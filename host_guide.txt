MONKEY INC BOT: HOST GUIDE
===========================

Host commands are /cq_host, /cq_config, /player and /character. Each shows a panel of
buttons; the buttons run the tools or open pop-ups. You can use them if you have the host
role (HOST_ROLE_ID) or the Manage Server permission. Replies are only visible to you.

Players use the commands in user_guide.txt. Read that first so you know what players see.


HOST COMMANDS AT A GLANCE
-------------------------
  /cq_host    panel: week dropdown + Status, Availability, Prep Roster, Player availability,
              Damage history, Post reminder now buttons
  /cq_config  settings panel: Reminders, Damage logs, Squad time, Remove squads, reminders
              on/off and Import roster buttons
  /player     panel: Add, Change, Link buttons
  /character  panel: Add, Change, Remove buttons


WHO CAN SEE THE HOST COMMANDS
-----------------------------
/cq_host, /cq_config, /player and /character are hidden from the command list for everyone
except members with the Manage Server permission. Discord doesn't let a bot show commands
to a role by itself, so a server admin does this once for EACH of the four:

  1. Server Settings > Integrations > Monkey Inc. > Manage.
  2. Under Commands, click /cq_host (then /cq_config, /player and /character).
  3. Add the host role (the one in HOST_ROLE_ID) and set it to allowed (✅).

Hosts may need to restart Discord (or press Ctrl+R / Cmd+R) before they appear.

Visibility only affects the command list. Every one of these commands also checks that the
user has the host role (or Manage Server), so even someone who sees it can't use it without
that role.

Optional: to show the player commands only to your player role, go to the same page. Under
Roles & Members at the top, add @everyone and set it to denied (❌). Then add the player
role and set it to allowed (✅). Keep the host-role overrides from step 3 in place.


KEY IDEAS
---------
- Squad order: every list of squads starts in time order. 🔀 "Sort by squad #" (on
  Availability, a player's availability, /cq_config's squad times,
  and the player screens) switches to squad-number order. It's remembered per person and
  used on every screen until you switch back with 🔀 "Sort by time".
- Week: a week runs Sunday to Saturday in the bot's timezone (default US Eastern,
  BOT_TIMEZONE). The week dropdown at the top of /cq_host chooses "Next week (upcoming)"
  (the default) or "This week (current)" for Status, Availability, Prep Roster and Player
  availability.
- Availability levels: 🟢 Preferred, 🟡 Available, 🔴 Not Available.
- Default vs. weekly: every player has a default schedule. For any week, the bot uses the
  player's weekly update if they submitted one. Otherwise it uses their default.
- Confirmed: a player counts as confirmed for a week once they press "No change" or save a
  weekly update. Viewing their schedule doesn't count.
- Advance submissions: players can change their availability for any of the next 8 weeks
  ("Update a future week" in /cq availability). Those changes count as confirmed for that week. They show up in
  Status and Availability once that week is "next week" or "this week".
- Player status:
    active     Normal roster member. Counted in Status and Availability.
    inactive   Not currently running. Ignored by status and availability.
  (A CHARACTER's status is separate: see character status, ⭐ static / ⏳ flex /
  💤 inactive.)
- Slotting stays in the Google Sheet. The bot learns squads and slot status when you upload
  the sheet with /cq_config > Import roster.


1. CHECKING AVAILABILITY
------------------------
/cq_host > 📋 Status
    How many ACTIVE players have confirmed (e.g. 41 / 73), with one line each for
    ✅ No change, ✏️ Updated and ⏳ Not confirmed yet. Lists every player who SUBMITTED A
    SCHEDULE CHANGE for the week. Look up someone's changed
    schedule with 👤 Player availability.
    The 👤 "See individual availability" button (shown when someone changed their week)
    opens one private message with a dropdown of everyone who submitted a schedule change,
    with how many squads they changed. Pick one and that message shows exactly what changed
    from their default, e.g. "Squad 4 · ...: 🟢 Preferred → 🔴 Not Available", plus any
    characters they changed for just this week, followed by their full availability for the
    week (with the 🔀 sort toggle). Pick someone else and the same message updates; no new
    message each time.
    The 📋 "Open availability" button opens the Availability view for the same week
    (as a new message, so the status stays above it).
    It also lists CHARACTER STATUS CHANGES from the last 7 days, with before and after:
        Alice: Ace (NL) ⭐ Static → 💤 Inactive
        Bob: Bolt (NL) ⭐ Static → ⏳ Flex (by host)
    If a character changed more than once, you see where it started and where it ended up;
    one changed and then changed back isn't listed. "(by host)" = changed with
    /character > Change rather than by the player. Every change is kept in the bot's database.

/cq_host > 📊 Availability
    Availability for every active player, by name. Buttons underneath switch what's shown; the
    one for what's on screen is blue (the message opens on Overview):
      📋 Overview                   How many players are 🟢 / 🟡 / 🔴 for each squad.
      🟢 Preferred / 🟡 Available   Every squad with the players at that level (names).
                                    ⏳ marks players who only have ⏳ Flex characters at that
                                    level; they're listed after players with a static
                                    character.
      🔀 Sort by squad # / time     The order of the squads.
    For each squad's CHARACTERS (to slot them), use Prep Roster.

/cq_host > 🧾 Prep Roster
    One squad at a time: the characters at 🟢 Preferred or 🟡 Available, for slotting. It opens
    on the first squad. Pick another from the squad dropdown (each squad shows how many are
    preferred and available), and switch level with 🟢 Preferred / 🟡 Available.

    Grouped by class (the default), under role headings, on these pages:
        Page 1  HP:   DRK, ARAN
                BSP:  BSP
                SI:   BUCC, TB
        Page 2  CRIT: DB, BM, MM, WA
        Page 3  DPS:  every other class, A-Z
      Use ◀ ▶ to move between pages. A page with no characters is skipped.
      Each class shows its icon and a count, e.g. "<icon> DRK (6)", then one line per
      character: damage - name, e.g. "• 4.3b - ragu". Damage is in billions (27.5-minute
      scale), rounded down to one decimal (3.08 -> 3.0b), in a shaded box so it's easy to
      skim; "?" = no damage recorded.
      Order: static characters first, then ⏳ Flex ones; each highest damage first (no
      damage last). Inactive characters are left out.

    🔀 "Group by player" switches to players A-Z, each with their characters as bullets
    (class icon and name, or "ragu/DRK" without an icon), ordered:
        1. static, then ⏳ flex
        2. class group: Warrior (HERO PAL DRK DW ARAN), Magician (FP IL BSP BW EVAN),
           Archer (BM MM WA), Thief (NL SHAD DB NW), Pirate (BUCC SAIR TB)
        3. character name
    🔀 "Group by class" switches back.
    Busy squads spread over pages (◀ ▶). In either grouping, anything too long for one page
    continues on the next, marked "(cont.)" in the class view.

    Availability here is per character: the player's weekly change (or default), then the
    character's ongoing exceptions ("Character availability" in /cq characters; when both
    exist, the less available one counts), then anything set for that character for this
    week only ("Change a character's week" in /cq availability), which wins.

/cq_host > 👤 Player availability
    Type a player (name, Discord username, or one of their characters) in the pop-up. Shows
    their availability for the week (their weekly update, or their default if they didn't
    submit one), their confirmation, and their characters with any per-character overrides.


2. MANAGING PLAYERS
-------------------
Only hosts can add or change players and characters. Players can view their characters
(/cq characters) and set their own availability, but can't edit the roster.

/player
    Shows three buttons. Each opens a pop-up. Players are TYPED (their name, Discord
    username, or one of their characters) and matched when you submit; if no single player
    matches, nothing is saved and the bot suggests close matches. Discord accounts are
    picked with Discord's member picker, which can search.

  ➕ Add      Name, Discord account (recommended), Discord username (only if they're not in
              the server yet; they're linked automatically the first time they use the bot)
              and Status (Active by default). Then add their characters with /character.
              The player sets their usual availability with "Change default availability"
              in /cq availability.
  ✏️ Change   Type the player; the bot shows their details (Discord account, status,
              characters) with an Edit button. Edit opens a pop-up filled in with their Name
              and Status. Only what you change is saved.
              Shortcut: /player change:<name> searches as you type. Pick the player and their
              edit pop-up opens straight away.
  🔗 Link     Player and Discord account. Use this when a player's Discord username changed
              and the bot says it can't find them. Players are otherwise linked automatically
              the first time they use the bot.

/character
    Shows three buttons. Each opens a pop-up. Pop-ups can't search, so you TYPE player and
    character names; they're matched when you submit (capitals don't matter). A player can be
    typed as their name, Discord username, or one of their characters. If no single match is
    found, nothing is saved and the bot suggests close matches.

  ➕ Add      Player, In-game name, Job (dropdown; each job shows its buff, e.g. "Buff: HSH"),
              Damage (optional) and Status (Static by default). You never enter a buff: it
              always comes from the job (see "Buffs" below).
  ✏️ Change   Type the character's in-game name; the bot shows its details with an Edit
              button. Edit opens a pop-up filled in with its Job, Damage, Status and
              "Move to player" (leave empty to keep the owner). Only what you change is saved.
              Changing the job also changes the buff to the new job's.
              The damage you enter is a fallback: once the character has runs from uploaded
              damage logs, those take priority. Moving a character keeps its damage history,
              character-specific availability and status.
              Shortcut: /character change:<name> searches as you type. Pick the character and
              its edit pop-up opens straight away, with no in-between message.
  🗑️ Remove   Type the player; the bot lists their characters with a button that opens a
              pop-up of checkboxes. Tick one or more and submit to remove them, including their
              damage history and availability overrides. This can't be undone.

Buffs
  Every character's buff comes from its job (class); nobody enters it:
    DPS     ARAN, BW, DW, EVAN, FP, HERO, IL, PAL, SAIR
    HASTE   NL, NW, SHAD        SE      BM, MM, WA        HSH     BSP
    SI/TL   BUCC                SI      TB                THORNS  DB        HB   DRK
  A job that isn't listed has no buff (shown as "?"). The table is db.JOB_BUFFS in the code.

Character status (⭐ static / ⏳ flex / 💤 inactive) shows which characters a player wants
slotted. Players choose Static or Flex themselves with the "Set character status" button in
/cq characters. Only hosts can mark a character 💤 Inactive (or change it back), with
/character > Change (Status); players see inactive characters as
locked. It starts as Static for
characters marked Perm on the sheet, Flex otherwise; Import roster never changes it.


3. UPDATING THE ROSTER FROM THE GOOGLE SHEET
--------------------------------------------
/cq_config > 📥 Import roster
    In Google Sheets: File > Download > Comma Separated Values (.csv) on the CQ Roster tab.
    Then press Import roster and upload that file in the pop-up.

    What it does:
      - Updates every character's job, dmg, run time, squad, slot status and perm. The
        buff comes from the job; the sheet's Buff column is ignored.
      - Adds new players and characters it hasn't seen before. New players start as
        active, with a default schedule taken from the sheet's Squad 1..N columns.
    Damage from the sheet (Dmg/27.5, or Dmg when that's empty) is assumed to be already
    scaled to a 27.5-minute run, so it's stored as-is. It's only used for characters
    with no uploaded damage logs.
    What it does NOT change:
      - Player statuses (active/inactive).
      - Availability players already set in the bot (default, weekly or per-character).
      - Characters that are in the bot but missing from the CSV (they're listed in the reply).

    The CSV is matched by column names (IGN, Name, Discord, Job, Squad, Dmg, Run time,
    Perm, Status, Squad 1..N), so extra or reordered columns are fine.


4. SQUAD TIMES
--------------
The bot keeps a recurring weekly schedule for each squad (day + time in the bot timezone),
first loaded from bot_data/squad_timings.txt. You can move a squad for one week, or change
it permanently.

/cq_config
    Shows next week's squad times, in your own timezone. Squads moved for just that week are
    marked ✏️.

/cq_config > 🕒 Squad time
    A pop-up: pick the squad (or "➕ New squad"), the day, a 24-hour time in the bot timezone
    (e.g. 21:30), and what to change:
      Next week only (default)   Moves the squad for NEXT WEEK only.
      Every week                 Changes the recurring schedule for all future weeks.
                                 Also use this to ADD a new squad.
      Reset next week            Undoes next week's one-off move for that squad, putting it
                                 back on the recurring schedule. Day and time aren't needed.
    Tip: Daylight saving changes can shift the game server's times relative to Eastern.
    When that happens, use Every week to update the recurring schedule.

/cq_config > 🗑️ Remove squads
    A pop-up with a dropdown of the squads: pick one or more to remove them from the schedule
    permanently.


5. WEEKLY REMINDERS
-------------------
The bot automatically posts the reminder (with the View my availability / No change / Update
this week buttons) in the CQ channel for the upcoming week. By default it posts twice:
Wednesday and Friday at 18:00 (bot timezone).

The reminder @mentions the player role set in PLAYER_ROLE_ID (in .env.prod). This includes
reminders posted with /cq_host > Post reminder now. Leave PLAYER_ROLE_ID empty for no ping. The role
must allow @mentions (Server Settings > Roles > "Allow anyone to @mention this role"),
otherwise the mention shows but nobody is notified.

The reminder message is the same for everyone. Each player's personal availability appears
only to them when they press "View my availability".

/cq_config
    Shows the current settings and this cycle's reminder and deadline times.
    ⏰ Reminders opens a pop-up, filled in with the current settings:
      Channel        where the reminder is posted
      Reminder days  pick one or more days from the dropdown
      Reminder time  24-hour, bot timezone. The same time is used for every reminder day.
      Deadline day / Deadline time
    🔕 / 🔔 "Turn automatic reminders off/on" switches the automatic posting.
    Defaults: reminders Wednesday and Friday 18:00, deadline Saturday 12:00 (the week
    before the squads run).
    Changing the days or time only affects future reminders. The bot won't immediately
    post one whose new time has already passed.
    The deadline is shown in the reminder. Players can still submit after it.

/cq_host > 📣 Post reminder now
    Asks first, then (when you press Post now) posts the reminder for next week immediately,
    in the configured channel (or the current channel if none is set). If a scheduled reminder is due at that moment, it won't
    also be posted. Later scheduled reminders still go out as normal.

If the bot is offline when a reminder is due, it posts the missed reminder when it comes
back up. Reminder buttons keep working after the bot restarts. A reminder for a week that
has already finished no longer accepts changes.


6. CLASS ICONS
--------------
Prep Roster shows a class icon next to each character. The
icons come from image files in bot_data/class_icons/ on the machine running the bot:

    bot_data/class_icons/DRK.png
    bot_data/class_icons/NL.png
    bot_data/class_icons/BSP.png   ... one per class, named exactly like the Job on the roster

  - PNG, JPG or GIF, up to 256 KB. A square image around 128x128 works best.
  - The bot checks the folder when it starts and every 10 minutes after that:
      new file       -> uploaded
      changed file   -> replaced
      deleted file   -> icon removed (the class name shows instead)
  - A file Discord rejects (e.g. too large) is skipped, and the reason is written to the
    bot's log. It's retried once you replace the file.
  - If the folder doesn't exist, existing icons are left as they are.
  - Classes without an icon show as "ragu/DRK".
Icons are stored by Discord as the bot's own emoji, so they work in any server and don't
use your server's emoji slots. The folder is git-ignored (class art is usually the game's
copyrighted artwork), so copy it to the server yourself, like the rest of bot_data/.


7. DAMAGE LOGS (#queen-logs)
----------------------------
After a run, post the damage log .txt file in #queen-logs as a normal message attachment
(drag and drop). You can attach several logs to one message. Only hosts' uploads are
processed. Files posted by anyone else are ignored.

The bot reads the bottom of the file:
    [Start Time] 27-09-2026 01:50:49        <- game server time (LOG_TIMEZONE, Sydney)
    [Finish Time] 27-09-2026 02:15:09
    >>CharacterName: 4,027,079,300 | deaths: 2

What happens:
  - Each character's damage for the run is scaled to a 27.5-minute run, in billions:
        damage / 1,000,000,000 x 27.5 / run minutes
    e.g. 4,027,079,300 over 24.3 minutes -> 4.55
  - The character's damage becomes the AVERAGE OF THEIR LAST 3 RUNS (change the number
    with /cq_config > 📊 Damage logs). This is the "dmg" shown by /cq characters.
  - The bot reacts ✅ when a log is saved. It replies only if something needs attention.
  - Names the bot can't match to a roster character are FLAGGED: the bot adds a ⚠️
    reaction and replies to you (with a ping) listing those names. Everyone else in the
    log is still saved as normal.
  - Names are matched to characters on the roster, ignoring capital letters.

The bot replies when:
  - Names aren't on the roster (⚠️, pings you). Only those names are skipped. Check the
    spelling, or add the character (/character > Add or /cq_config > Import roster), then
    post the same log again. Only the missing characters are added; the rest of the run
    isn't counted twice.
  - The run was already uploaded (same start and finish time). Nothing is saved twice.
  - The file isn't a damage log (no start/finish time or damage lines).

Undo: delete your upload message. The bot removes that run and recalculates damage for
everyone in it. A character with no runs left goes back to their damage from the roster
sheet, or the value they entered.

Damage from logs always takes priority. Import roster and /character > Change (Damage) only
change the fallback value, used while a character has no logged runs.

/cq_config > 📊 Damage logs
    /cq_config shows the settings; the button opens a pop-up. Channel: where logs are posted
    (left empty: any channel named #queen-logs). Runs to average: how many recent runs to
    average (1–50, default 3). Changing it recalculates every character.

/cq_host > 📈 Damage history
    Type the character's in-game name in the pop-up. Shows the character's current damage and their last 15 runs: raw damage, run length, and
    scaled damage. ★ marks the runs counted in the average.


8. TROUBLESHOOTING
------------------
- "Only hosts can use this command": you need the host role or the Manage Server
  permission.
- No reminder posted: check /cq_config. Are reminders on, and is a channel set?
  Does the bot have permission to send messages and embeds in that channel?
- A player can't be found: link them to their Discord account with /player > Link.
- Wrong squad times: check them in /cq_config, then fix them with its Squad time button.
- A damage log got no ✅ and no reply: check it was posted in the logs channel
  (/cq_config), as a .txt attachment, by someone with the host role.
